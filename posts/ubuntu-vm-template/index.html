새 VM의 바탕으로 남겨 둔 Ubuntu 템플릿

10G 시스템 디스크와 Cloud-Init 드라이브를 둔 Ubuntu 24.04 템플릿. 기본 자원과 부팅 장치, 실제 서비스 VM에서 달라지는 설정을 비교한다.

Chihun2026년 10월 22일수정 2026년 11월 26일6분 읽기

Proxmox 홈서버에 Ubuntu 24.04용 VM 템플릿을 남겨 뒀다. 10G 시스템 디스크에 Cloud-Init 드라이브를 붙이고 template: 1로 표시한 구성이다. 실행할 서비스를 담은 VM 옆에, 새 환경의 바탕으로 사용할 항목을 따로 마련했다.

템플릿에는 작은 기본 자원만 남겼다

2026년 10월 22일 기준으로 템플릿에는 CPU 2코어와 메모리 2048MiB가 할당돼 있다. 같은 서버의 NAS가 24GiB, 데이터 처리 VM이 6GiB인 것과 비교하면 이쪽은 기본 환경을 담는 작은 구성이다.

항목설정
템플릿 표시template: 1
CPU1소켓 · 2코어, x86-64-v2-AES
메모리2048MiB, 즉 2GiB
머신 · 펌웨어q35 · OVMF(UEFI)
시스템 디스크scsi0, local-lvm, 10G
SCSI 컨트롤러virtio-scsi-single
네트워크VirtIO NIC → vmbr0, firewall=1

시스템 디스크에는 discard=on,iothread=1,ssd=1이 들어 있다. NAS·데이터 처리 VM의 시스템 디스크에서도 사용하는 옵션이다. 다만 같은 디스크 옵션을 쓴다는 사실만으로 어느 VM이 이 템플릿에서 복제됐는지 알 수는 없다.

Cloud-Init은 ide0, 부팅은 scsi0

이 템플릿에는 시스템 디스크와 별개의 Cloud-Init 드라이브가 있다. 연결 위치는 ide0이며 CD-ROM 매체로 표시된다. 실제 부팅 순서는 scsi0만 가리킨다.

Text
boot: order=scsi0
ide0: local-lvm:<Cloud-Init 볼륨>,media=cdrom
scsi0: local-lvm:<템플릿 시스템 볼륨>,discard=on,iothread=1,size=10G,ssd=1
scsihw: virtio-scsi-single
template: 1

역할은 둘로 나뉜다. scsi0에는 운영체제 디스크가 있고, Cloud-Init 드라이브는 새 환경에 전달할 초기 설정을 담는 매체다. Cloud-Init 드라이브를 붙였다고 운영체제 부팅 대상을 그 드라이브로 바꾸는 것은 아니다. Proxmox의 Cloud-Init 드라이브와 부팅 설정

문서의 예제에서는 Cloud-Init 드라이브가 ide2에 있지만, 내 템플릿에서는 ide0에 있다. IDE 장치는 0부터 3까지 설정할 수 있다. 예제의 슬롯 번호만 찾으면 실제로 연결된 드라이브를 놓칠 수 있는 부분이다. IDE 장치 설정 범위

실제 서비스 VM에서는 주소와 디스크 크기가 달라진다

같은 서버에서 Cloud-Init 드라이브를 사용하는 개발용 VM과 데이터 처리 VM도 함께 비교했다.

항목Ubuntu 템플릿개발용 VM데이터 처리 VM
Cloud-Init 드라이브ide0ide0ide0
시스템 디스크10G80G40G
메모리2GiB8GiB6GiB
ipconfig0명시된 항목 없음ip=dhcp고정 주소·게이트웨이 지정

개발용 VM에는 DHCP 설정이, 데이터 처리 VM에는 고정 주소와 게이트웨이가 들어 있다. 템플릿에는 ipconfig0 항목이 명시돼 있지 않다. Proxmox 문서에서는 Cloud-Init이 활성화되고 IPv4·IPv6 주소를 모두 지정하지 않으면 IPv4 DHCP를 기본값으로 사용한다고 설명한다. 따라서 항목이 없다는 사실을 네트워크 설정 자체가 없다는 뜻으로 읽으면 안 된다. 실제 게스트에 적용된 주소는 별도로 확인하지 않았다. Cloud-Init 네트워크 옵션

이 표는 현재 구성의 비교다. 두 서비스 VM을 이 템플릿에서 복제했다는 이력이나 디스크 확장 명령의 실행 기록은 없어, 디스크 크기의 차이만으로 생성 순서를 알 수는 없다. 실제로 개발용 VM에 접속하고 도구를 설치한 과정은 개발용 VM 글에 따로 적었다.

중지 상태가 이 항목의 역할과 맞는다

템플릿은 목록에서 stopped로 보인다. NAS처럼 켜져 있어야 파일을 제공하는 항목과 달리, 복제할 바탕을 보관하는 항목이므로 같은 기준으로 실행 상태를 판단할 수 없다. Proxmox 문서에서도 준비한 이미지를 템플릿으로 만들고 복제하는 흐름을 설명한다. 템플릿과 Cloud-Init

현재 마련해 둔 것은 시스템 디스크, Cloud-Init 매체, 가상 하드웨어를 묶은 기반이다. SSH 키와 Tailscale 인증, 애플리케이션 설치까지 자동으로 끝나는 환경으로 시험한 것은 아니다. 새 서비스 VM으로 사용할 때 달라지는 주소·자원·접속 설정은 템플릿 바깥의 작업으로 남는다.
