Proxmox에 Home Assistant VM을 올려 봤다

Chihun2026년 10월 22일5분 읽기

Proxmox에 홈 자동화용 VM을 따로 만들고 Home Assistant Core와 Supervisor를 올렸다. 여기에 Matter, Tailscale, SSH add-on을 함께 구성했다. NAS가 파일을 맡고 데이터 처리 VM이 데이터베이스를 맡는 것처럼, Home Assistant 환경도 자기 디스크와 네트워크 인터페이스를 가진 VM으로 나눴다.

2코어와 4GiB, 로컬 디스크로 만든 환경

2026년 10월 22일 기준으로 이 VM에는 CPU 2코어와 메모리 4096MiB를 할당해 뒀다. 디스크는 32G이며 Proxmox의 local-lvm에 있다. Home Assistant가 사용하는 시스템 디스크를 NAS의 SMB 공유에 둔 구성은 아니다.

항목설정
CPU1소켓 · 2코어, cpu: host
메모리4096MiB, 즉 4GiB
머신 · 펌웨어q35 · OVMF(UEFI)
시스템 디스크sata0, local-lvm, 32G
부팅 대상order=sata0
네트워크VirtIO NIC → vmbr0, firewall=1

이 VM의 부팅 디스크는 sata0다. 같은 서버의 NAS나 개발용 VM에서 사용하는 scsi0와 연결 위치가 다르다. VM 설정에 SCSI 컨트롤러 항목도 있지만, 실제 부팅 대상은 SATA 디스크로 지정돼 있다.

Text
bios: ovmf
boot: order=sata0
cores: 2
memory: 4096
sata0: local-lvm:<시스템 볼륨>,discard=on,size=32G,ssd=1

discard=on과 ssd=1도 이 디스크에 들어 있다. 각각 게스트의 discard 요청을 아래 저장소로 전달하는 옵션과 SSD라는 장치 특성을 게스트에 알려 주는 옵션이다. 이 값이 애플리케이션의 성능 측정 결과를 뜻하지는 않는다. Proxmox 디스크 옵션

Home Assistant 옆에 접속 통로도 함께 뒀다

VM 안에는 Core와 Supervisor뿐 아니라 Matter와 원격 접속용 add-on도 있었다. 당시 서비스 기록에 남은 구성은 다음과 같다.

구분올려 둔 구성
Home AssistantCore, Supervisor
기기 연결 관련Matter
원격 접속 관련Tailscale, SSH add-on

네트워크 인터페이스는 다른 VM들과 같은 vmbr0에 연결했다. Proxmox에서 VM까지 이어지는 기본 네트워크와 VM 안에 설치한 Tailscale·SSH add-on이 함께 있는 구조다. Proxmox 호스트에 SSH로 들어가는 것과 Home Assistant VM 안으로 들어가는 것은 목적지가 다르다.

여기까지는 홈 자동화 환경과 접속 수단을 갖춘 작업이다. Matter의 설치와 기기 페어링, 실제 제어는 각각 다른 단계다. 기기별 연결과 자동화 규칙의 실행은 별도 시험이 필요한 부분으로 남아 있다.

NAS 뒤에 시작하도록 둔 순서

호스트가 켜질 때의 설정은 onboot: 1, startup: order=50,up=30이다. 같은 서버의 NAS는 order=10,up=10이므로 자동 시작 순서상 NAS가 앞에 있다.

Text
NAS VM             order=10, up=10
Home Assistant VM  order=50, up=30

이 숫자는 서비스 간 연결을 검사하는 규칙이 아니다. up=30은 이 VM을 시작한 뒤 다음 시작 대상으로 넘어가기 전에 기다리는 시간이다. Home Assistant 초기화나 NAS 공유 준비가 끝났다는 응답을 기다리는 설정은 아니다. 자동 시작 순서와 대기 시간

2026년 10월 22일에는 Home Assistant VM을 중지해 둔 상태다. 자동 시작 설정은 남아 있지만 현재 전원이 켜져 있다는 뜻은 아니다. Core·Supervisor와 add-on을 올려 봤던 환경은 이 32G 디스크를 가진 VM으로 보관하고 있다.
