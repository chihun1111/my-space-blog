PostgreSQL과 데이터 처리 서비스를 한 VM에 모았다

Chihun2026년 10월 22일6분 읽기

Proxmox의 데이터 처리 VM에는 PostgreSQL과 classifier-api, fetcher, resolver, doc-pipeline을 함께 올렸다. 서비스마다 VM을 하나씩 만든 대신, 데이터베이스와 처리 프로그램을 한 환경에 모았다. 파일과 VM 백업을 보관하는 TrueNAS는 별도 VM으로 두고 있다.

데이터 처리 VM에 할당한 자원

2026년 10월 22일의 구성은 2코어, 메모리 6GiB, 시스템 디스크 40G다. 부팅 디스크는 Proxmox의 local-lvm에 있으며 virtio-scsi-single 컨트롤러를 사용한다.

항목설정
CPU1소켓 · 2코어, cpu: host
메모리6144MiB, 즉 6GiB
머신 · 펌웨어q35 · OVMF(UEFI)
시스템 디스크scsi0, local-lvm, 40G
디스크 옵션discard=on, iothread=1, ssd=1
네트워크VirtIO NIC → vmbr0, firewall=1

VM을 따로 둔 덕분에 Proxmox에서 이 환경의 CPU·메모리와 전원 상태를 하나의 단위로 다룰 수 있다. 다만 같은 VM 안의 프로그램은 이 자원을 함께 쓴다. PostgreSQL과 네 서비스 각각에 6GiB씩 할당한 구성이 아니다.

iothread=1은 가상 디스크의 I/O를 별도 스레드에서 처리하도록 한 설정이다. 이 옵션과 40G 디스크 크기는 VM의 구성값이며, 데이터베이스 처리량이나 실제 데이터 크기를 나타내지는 않는다. Proxmox 디스크와 I/O 스레드

Cloud-Init 디스크와 고정 주소 설정

이 VM에는 시스템 디스크와 별도로 Cloud-Init 디스크가 ide0에 연결돼 있다. 부팅 순서는 scsi0;ide2;net0이며 시스템 디스크가 먼저다. Cloud-Init 디스크를 운영체제 부팅 디스크로 지정한 구성은 아니다.

네트워크 초기 설정인 ipconfig0에는 고정 주소와 게이트웨이가 들어 있다. 개발용 VM의 ip=dhcp와는 다른 부분이다. 실제 주소를 제외하면 설정의 형태는 아래와 같다.

Text
boot: order=scsi0;ide2;net0
ide0: local-lvm:<Cloud-Init 볼륨>,media=cdrom
ipconfig0: ip=<고정 주소/CIDR>,gw=<게이트웨이>
scsi0: local-lvm:<시스템 볼륨>,discard=on,iothread=1,size=40G,ssd=1

Cloud-Init 드라이브는 초기 설정을 전달하는 매체이고, ipconfig0는 그중 네트워크 설정이다. 위 내용은 Proxmox에 저장된 값이다. 게스트 안에서 현재 쓰는 주소까지 이번 조회로 대조한 것은 아니다. Cloud-Init 드라이브, 네트워크 설정 형식

PostgreSQL 옆에 네 서비스를 함께 올렸다

기존 서비스 기록에는 PostgreSQL과 네 처리 프로그램이 함께 남아 있다. 당시 관측 포트는 5432, 8010, 8011, 8012, 8013이다.

구분같은 VM에 둔 항목
데이터베이스PostgreSQL
처리 프로그램classifier-api, fetcher, resolver, doc-pipeline
당시 관측 포트5432, 8010–8013

8010–8013의 개별 서비스 대응 관계와 처리 순서는 이 포트 목록에 남아 있지 않다. PostgreSQL과 네 프로그램을 함께 올린 구성은 있지만, 서비스 이름만으로 데이터가 어떤 순서로 오가며 최종 저장되는지 알 수는 없다. 각 API의 응답과 실제 데이터 저장 결과까지 이어 보는 시험은 별도다.

켜진 VM 안으로 들어가려다 만난 게스트 에이전트 상태

자동 시작은 onboot: 1, startup: order=50,up=30이다. NAS의 order=10보다 뒤에 시작하도록 돼 있다. 이 순서는 NAS나 데이터베이스가 준비됐는지를 확인하는 상태 검사가 아니다. Proxmox 시작 순서

2026년 10월 22일에는 VM 자체가 실행 중이었다. 설정에는 agent: 1도 있었지만 게스트 에이전트를 통한 명령 조회는 아래 오류로 끝났다.

Text
QEMU guest agent is not running

Proxmox에서 에이전트를 사용하도록 설정한 것과 게스트 안에서 에이전트가 응답하는 것은 달랐다. 이 경로로는 내부 서비스 상태와 열린 포트를 다시 읽지 못했다. 따라서 현재 실행 중인 VM이라는 상태와 과거에 올린 PostgreSQL·처리 서비스 목록은 구분해 둔다. SQL 실행과 전체 데이터 처리 흐름은 별도 접속과 기능 시험이 필요한 부분이다.
