홈서버 VM마다 CPU와 메모리를 다르게 둔 구성

NAS와 개발 환경, 게임 서버에 CPU와 메모리를 다르게 줬어요. VM마다 얼마나 나눴는지 한 번에 정리했어요.

Chihun2026년 10월 22일수정 2026년 11월 26일5분 읽기

제 홈서버의 VM은 모두 같은 크기가 아니에요. NAS에는 메모리 24GiB를, 개발용 VM에는 8GiB를 할당해 뒀고, Ubuntu 템플릿은 2GiB예요. 서비스 이름뿐 아니라 가상 하드웨어 설정도 서로 다르게 남아 있어요.

VM 10개에 배정한 자원

2026년 10월 22일 기준 CPU·메모리 설정과 전원 상태예요. 메모리는 memory 값을 MiB에서 GiB로 환산했어요. 설정된 크기이므로 현재 사용량을 나타내는 표는 아니에요.

VM코어 수CPU 유형메모리상태
NAS6host24GiB실행 중
LiteKernel4host8GiB중지
개발용 Hermes4x86-64-v2-AES8GiB실행 중
WOL2host4GiB실행 중
Home Assistant2host4GiB중지
n8n2host6GiB중지
데이터 처리2host6GiB실행 중
MinCrafty4host6GiB중지
Linux Mint8host16GiB중지
Ubuntu 템플릿2x86-64-v2-AES2GiB중지

소켓 수는 대부분 sockets: 1로 명시돼 있어요. Home Assistant에는 소켓 항목이 생략돼 있고, Proxmox의 기본값도 1이에요. 그래서 이 구성에서는 표의 코어 수가 VM의 vCPU 수와 같아요. 물리 CPU 코어를 그 수만큼 해당 VM에 전용으로 고정했다는 뜻은 아니에요. CPU·소켓 설정

NAS의 자원 설정을 펼치면 아래와 같아요.

Text
cores: 6
sockets: 1
cpu: host
memory: 24576
numa: 0

VM 목록에 남아 있는 모든 메모리 값을 더해서 현재 호스트의 사용량으로 볼 수도 없어요. 중지된 VM과 템플릿이 포함돼 있고, 실행 중인 VM의 메모리 사용량 역시 할당값과는 따로 확인해야 하는 값이에요.

코어 수와 CPU 유형은 다른 설정이에요

대부분은 cpu: host지만 개발용 VM과 Ubuntu 템플릿에는 x86-64-v2-AES가 들어 있어요. 코어 수는 가상 CPU의 개수이고, CPU 유형은 게스트에 보여 주는 CPU 기능과 관련된 설정이에요. host는 호스트 CPU의 기능을 노출하는 방식이에요. Proxmox CPU 유형 설명

현재 값만으로 제가 서로 다른 유형을 선택했던 이유나 성능 차이까지 알 수는 없어요. 개발 VM의 작업 기록에는 처음 메모리가 16GB였다는 내용이 있고 지금은 8GiB로 남아 있지만, 변경 이유와 시점은 기록돼 있지 않아요. 자원이 달라졌다는 사실과 변경 의도는 나눠 적었어요.

q35와 펌웨어도 따로 봐야 해요

열 개 VM의 머신 유형은 모두 q35예요. 펌웨어는 개발용 VM만 seabios이고 나머지는 ovmf예요. 머신 유형과 펌웨어는 별도 항목이라, q35라는 값만으로 UEFI 부팅이라고 판단할 수 없어요. OVMF는 UEFI 구현이에요. 머신 유형과 펌웨어

개발용 VM에는 efidisk0도 남아 있어요. 그런데 실제 bios 값은 SeaBIOS예요. EFI 디스크가 보인다는 이유만으로 OVMF를 사용한다고 읽으면 이 VM의 설정을 잘못 설명하게 돼요.

Text
개발용 VM
machine: q35
bios: seabios

Ubuntu 템플릿
machine: q35
bios: ovmf

VM 메모리와 앱 메모리는 나눠 봐요

MinCrafty의 6GiB는 VM 전체에 배정한 메모리예요. ATM10의 Java 최대 힙을 6GiB로 지정했다는 뜻은 아니에요. NAS의 24GiB 역시 그 안의 Nextcloud와 Immich에 각각 24GiB씩 배정한 값이 아니에요.

제 환경은 Proxmox의 VM 자원 → 게스트 운영체제 → 앱 또는 게임 프로세스로 이어져요. 어떤 메모리 값을 보고 있는지 먼저 구분해야 VM 설정과 앱 실행 옵션을 비교할 수 있어요.
