TrueNAS에 Immich를 올린 구성, 사진 저장소와 머신러닝 서비스

Chihun2026년 10월 22일5분 읽기

홈서버에는 파일용 Nextcloud와 별도로 사진 서버인 Immich도 올려 두었다. Immich는 사진을 담는 저장 공간 외에 서버, 데이터베이스, 작업 큐, 머신러닝 서비스가 함께 돌아간다. 내 TrueNAS에서도 이 역할들이 서로 다른 서비스로 나뉘어 있다.

2026년 10월 22일 기준 앱 버전은 v3.3.0, TrueNAS 앱 차트는 1.14.47이다. 앱은 실행 중이고 웹 포트는 2283으로 게시돼 있다.

사진 데이터는 tank에, DB는 앱 볼륨에 둔다

Immich의 data 항목은 tank 안의 호스트 경로에 연결돼 있다. Nextcloud 파일을 둔 단일 디스크 풀 nc_pool과는 다른 저장 위치다. tank는 4TB 디스크 두 개를 미러로 묶은 ZFS 풀이다.

저장 항목내 설정
앱의 데이터 영역 datatank의 host_path
PostgreSQL 데이터 postgres_dataix_volume
머신러닝 캐시 ml_cachetemporary
추가 저장소없음

사진 데이터를 두는 경로와 DB 볼륨은 분리돼 있다. 머신러닝 캐시도 사진 데이터와 같은 호스트 경로를 지정한 항목이 아니라 temporary로 설정돼 있다. 같은 앱에 속해 있어도 모두 같은 방식으로 보관되는 것은 아니다.

미러는 이 저장 경로 아래에 있는 디스크 구성이다. 사진을 실수로 삭제했을 때 이전 상태를 되돌리는 백업과는 역할이 다르다. 또 사진 파일 경로와 DB가 따로 있으므로 앱 전체를 옮기거나 복구할 때는 두 영역을 함께 다뤄야 한다. Immich의 공식 구조 설명에서도 파일을 처리하는 서버와 영구 메타데이터를 보관하는 PostgreSQL을 구분한다.

서버와 머신러닝을 별도 서비스로 실행한다

현재 실행 중인 서비스는 네 개다.

서비스 이름현재 구성
serverImmich 서버
pgvectoPostgreSQL 18 · VectorChord 1.1.1 이미지
redisValkey 9.1.2 이미지
machine-learning머신러닝 서비스

pgvecto나 redis라는 서비스 이름만 보고 실행 제품을 단정하면 실제 이미지와 어긋난다. 내 구성의 DB 이미지에는 VectorChord가 포함돼 있고, Redis 역할의 서비스는 Valkey 이미지를 사용한다.

공식 구조에서 서버는 API와 백그라운드 작업을 처리하고, PostgreSQL은 메타데이터를 보관한다. Redis는 작업 큐를 지원하며 머신러닝은 별도 서비스가 맡는다. 이 구조를 내 서비스 목록과 맞춰 보면 사진 서버를 웹 프로세스 하나로만 볼 수 없는 이유가 드러난다. Immich 구성 요소별 역할

내 앱에서는 enable_ml이 켜져 있고 machine-learning 서비스도 실행 중이다. 기능을 켠 상태와 실제 사진으로 얼굴 인식·검색 작업을 끝낸 상태는 구분해야 한다. 여기서 설명하는 것은 머신러닝 서비스를 포함해 앱을 실행한 구성이다.

앱의 자원 제한 설정은 CPU 4, 메모리 8192 MB다. 메모리는 카탈로그 표기의 MB를 사용했다. Nextcloud의 CPU 2·4096 MB보다 큰 값이지만, 실제 CPU 사용률이나 처리 속도를 측정한 수치는 아니다. TrueNAS VM 안에서 각 앱에 지정한 제한이다.

2283 포트의 API 응답까지 확인했다

실행 상태에 더해 /api/server/ping으로 요청을 보냈다. HTTP 200과 다음 응답이 돌아왔다.

JSON
{"res":"pong"}

앱이 게시한 포트에서 서버 API까지 응답하는 상태다. 이 점검에는 사진 업로드, 모바일 자동 백업, 얼굴 인식 작업은 포함하지 않았다.
