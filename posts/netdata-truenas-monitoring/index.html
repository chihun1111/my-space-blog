TrueNAS에 Netdata를 붙여 서버 상태를 보는 환경 만들기

NAS 상태를 보려고 TrueNAS에 Netdata를 붙였어요. 포트와 저장 공간을 나누고, 어디까지 확인했는지 적어 뒀어요.

Chihun2026년 10월 22일수정 2026년 11월 26일5분 읽기

TrueNAS에는 파일·사진 앱과 함께 Netdata도 올려 뒀다. NAS 안에서 실행되는 모니터링 앱으로, Nextcloud와 Immich가 있는 환경에 상태를 볼 통로를 추가한 구성이다. 2026년 10월 22일에는 앱이 실행 중이었고 로컬 API도 응답했다.

Proxmox 호스트가 아니라 NAS 안에 둔 앱

내 NAS는 Proxmox의 VM이다. 그 VM 안에서 TrueNAS가 실행되고, Netdata는 TrueNAS Apps에 등록돼 있다. 따라서 이 글의 Netdata는 물리 Proxmox 호스트에 직접 설치한 에이전트가 아니다.

Text
Proxmox
  └─ TrueNAS VM
       ├─ Nextcloud
       ├─ Immich
       └─ Netdata

Netdata의 로컬 대시보드는 CPU 사용량을 비롯한 서버 상태를 보여 주는 화면이다. TrueNAS 앱의 Web Portal도 이 대시보드로 연결된다. 다만 앱 하나가 실행 중이라는 이유로 다른 VM이나 물리 호스트 전체까지 수집하도록 구성됐다고 볼 수는 없다. TrueNAS의 Netdata 대시보드 안내

19999 포트와 별도 앱 자원 제한

현재 앱의 설정값은 다음과 같다. 버전은 Netdata 자체 버전과 TrueNAS 앱 패키지 버전을 나눠 적었다.

항목2026년 10월 22일 구성
Netdata 버전v2.12.1
TrueNAS 앱 패키지1.4.19
앱 상태RUNNING
웹 포트19999, published
CPU 제한 설정2
메모리 제한 설정1024 MB, 카탈로그 표기 기준
실행 서비스netdata, running

이 제한값은 NAS VM 전체의 CPU·메모리와 별개인 앱 설정이다. 웹 포트의 published도 호스트 쪽에 포트를 연결하는 방식이며, 인터넷에 공개했다는 뜻으로 쓰지는 않는다. 외부 접속 여부는 네트워크 경로와 방화벽에 달려 있다.

설정·라이브러리·캐시를 각각 남기는 구성

스토리지 항목은 config, lib, cache로 나뉘며 세 항목 모두 ix_volume을 사용한다. 별도의 추가 스토리지 연결은 없다.

스토리지 항목연결 방식
config앱 관리 볼륨 ix_volume
lib앱 관리 볼륨 ix_volume
cache앱 관리 볼륨 ix_volume

사진 파일을 tank에 연결한 Immich나 파일 데이터를 nc_pool에 연결한 Nextcloud와 달리, Netdata의 이 세 저장 항목은 앱 관리 볼륨이다. 같은 NAS에서 실행해도 앱마다 필요한 저장 경로를 다르게 구성해 둔 셈이다.

SMART와 Intel GPU 수집 옵션은 모두 꺼져 있다. 그러므로 이 구성만 보고 디스크 SMART나 GPU 상태까지 수집하고 있다고 설명할 수는 없다. 모니터링 화면을 마련한 것과 어떤 항목을 수집하도록 켰는지는 구분해야 한다.

로컬 API가 설치된 버전을 반환했다

NAS 안에서 19999 포트의 /api/v1/info에 읽기 요청을 보냈다. HTTP 상태는 200이었고 응답의 버전 필드는 다음과 같았다.

JSON
{"version":"v2.12.1"}

앱 목록의 실행 상태와 HTTP 응답, 반환된 버전이 맞아떨어졌다. 이 결과는 Netdata의 정보 API까지 동작한다는 뜻이다. 경보 전달이나 특정 병목을 발견해 성능을 개선했다는 경험까지 포함하는 것은 아니다. 현재는 파일·사진 서비스를 올려 둔 NAS에 모니터링 앱과 응답 가능한 대시보드 포트를 함께 마련한 상태다.
