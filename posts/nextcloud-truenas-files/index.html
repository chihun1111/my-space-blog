TrueNAS에 Nextcloud를 올리고 파일과 DB 저장 공간을 나눴어요

TrueNAS에 Nextcloud를 올렸어요. 파일과 DB 저장 공간을 나누고, 백그라운드 작업과 상태 응답을 확인한 기록이에요.

Chihun2026년 10월 22일수정 2026년 11월 26일5분 읽기

TrueNAS에는 SMB 공유와 별도로 Nextcloud도 올려 두었어요. SMB가 공유 폴더를 여는 통로라면, Nextcloud는 웹 애플리케이션과 데이터베이스를 함께 운영하는 파일 서버예요. 제 구성에서도 사용자 파일, 앱 파일, PostgreSQL 데이터의 저장 방식이 나뉘어요.

2026년 10월 22일 기준 Nextcloud는 35.0.2, TrueNAS 앱 차트는 2.3.85예요. 앱은 실행 중이며 웹 포트는 30027로 게시돼 있어요.

사용자 파일은 nc_pool의 호스트 경로에 둬요

Nextcloud의 data 저장소는 nc_pool 안의 호스트 경로를 사용해요. 앱 설정에서 host_path로 연결한 공간이에요. 반면 html과 postgres_data는 TrueNAS가 관리하는 ix_volume으로 잡혀 있어요.

저장 항목제 설정구분하는 내용
datanc_pool의 host_path사용자 파일을 두는 공간
htmlix_volumeNextcloud 앱 파일 영역
postgres_dataix_volumePostgreSQL 데이터 영역

이 구분은 파일만 따로 꺼내 놓는 것과 앱 전체를 보존하는 일이 다르다는 점을 보여 줘요. 사용자 파일이 있는 경로와 DB가 있는 볼륨이 서로 달라서, 파일 경로 하나만 알아서는 Nextcloud의 전체 저장 구성을 설명할 수 없어요. TrueNAS의 Nextcloud 배포 안내도 앱 데이터, 사용자 파일, PostgreSQL 저장소를 각각 구분해요.

nc_pool은 2TB 디스크 하나로 만든 ZFS 풀이에요. 같은 NAS의 tank는 4TB 디스크 두 개의 미러지만, Nextcloud 파일을 둔 nc_pool에는 그 미러 구성이 적용되지 않아요. 앱의 저장 항목을 나누는 것과 디스크 장애에 대비한 복사본을 두는 일도 별개예요.

웹 앱 옆에서 DB와 주기 작업이 함께 돌아가요

실행 중인 서비스는 nextcloud, cron, postgres, redis 네 개예요. 웹 요청을 받는 앱 하나만 있는 구성은 아니에요.

PostgreSQL은 18 계열 이미지가 선택돼 있고, 실행 이미지의 태그는 18.6이에요. 서비스 이름이 redis인 컨테이너는 실제로 Valkey 9.1.2 이미지를 사용해요. 그래서 서비스 목록의 이름과 실행 이미지의 제품명을 구분해서 봐야 해요. Nextcloud 공식 문서에서는 Redis를 캐시와 파일 잠금에 쓰이는 구성 요소로 설명해요. 캐시 구성 문서

주기 작업은 별도의 cron 서비스가 맡아요. 제 앱에서는 cron이 켜져 있고 일정은 다음과 같아요.

Text
cron: enabled
schedule: */5 * * * *

5분마다 실행하도록 설정한 거예요. 사용자가 웹 화면을 여는 시점과 별도로 주기 작업을 실행하는 구성이며, 이 일정 자체가 개별 작업의 완료 기록은 아니에요. 이미지 처리용 Imaginary 옵션은 꺼져 있어요.

앱의 자원 제한 설정은 CPU 2, 메모리 4096 MB예요. 메모리 단위는 TrueNAS 카탈로그의 표기를 따랐어요. TrueNAS VM 전체에 할당한 6코어·24GiB와는 다른 층의 설정이에요. NAS VM 안에서 Nextcloud 외의 앱도 함께 실행되므로 VM 자원과 앱 제한을 같은 값으로 읽으면 안 돼요. 앱 카탈로그의 자원 설정

상태 API에서 설치 완료와 유지보수 상태를 확인했어요

웹 포트가 게시된 것에서 한 단계 더 들어가 /status.php에 요청했어요. HTTP 200과 함께 다음 값이 돌아왔어요.

JSON
{
  "installed": true,
  "maintenance": false,
  "needsDbUpgrade": false,
  "versionstring": "35.0.2"
}

이 응답으로 설치가 완료된 상태이며 유지보수 모드가 아니고, 앱이 DB 업그레이드를 요구하지 않는다는 점을 확인했어요. 파일 업로드·동기화나 복구까지 시험한 결과는 아니에요.
