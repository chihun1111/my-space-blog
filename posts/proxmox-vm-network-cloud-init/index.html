VM 네트워크를 vmbr0에 연결하고 Cloud-Init 주소를 나눴다

공통 vmbr0 브리지 위에서 개발 VM은 DHCP, n8n·데이터 VM은 고정 주소를 사용했다. NIC와 Cloud-Init, 원격 접속의 역할을 나눠 본다.

Chihun2026년 10월 22일수정 2026년 11월 26일5분 읽기

내 홈서버의 VM 열 개는 VirtIO 네트워크 인터페이스를 통해 같은 vmbr0에 연결돼 있다. 반면 IP 주소를 전달하는 Cloud-Init 설정은 VM마다 다르다. 개발용 VM은 DHCP를, n8n과 데이터 처리 VM은 고정 주소를 사용하도록 설정돼 있다.

vmbr0는 연결 위치, IP는 별도 설정

2026년 10월 22일 기준으로 열 개 VM의 net0에 공통으로 들어 있는 값은 아래 세 가지다.

항목값
네트워크 장치 모델virtio
연결 브리지vmbr0
VM NIC의 방화벽 옵션firewall=1

VirtIO는 게스트에 보여 주는 네트워크 장치의 종류이고, vmbr0는 그 인터페이스가 연결되는 호스트의 브리지다. 내 NAS 구성에서는 이 브리지가 물리 인터페이스와도 연결돼 있다. VM마다 브리지를 하나씩 만든 형태가 아니다. Proxmox 네트워크 장치 설명

이 공통 설정만으로 각 VM의 주소를 알 수는 없다. 같은 브리지에 연결된 VM도 주소를 받는 방식은 다를 수 있고, firewall=1 하나만으로 어떤 포트가 허용되는지도 정해지지 않는다. 이번 비교에서 VM NIC에 명시된 VLAN 태그는 없었다.

Cloud-Init 매체가 연결된 VM 네 개

초기 설정을 전달하는 Cloud-Init 매체는 개발·n8n·데이터 처리·Ubuntu 템플릿의 ide0에 있다. 저장 위치는 local-lvm이고 매체 형식은 CD-ROM이다.

VMCloud-Init 매체ipconfig0
개발용 Hermeside0ip=dhcp
n8nide0고정 주소·게이트웨이 지정
데이터 처리ide0고정 주소·게이트웨이 지정
Ubuntu 템플릿ide0명시된 항목 없음

이 드라이브는 운영체제를 담은 scsi0와 별개다. 시스템 디스크로 부팅하면서 Cloud-Init 매체로 초기 설정을 전달하는 구성이다. Proxmox Cloud-Init 설명

같은 ide0 매체를 사용한다고 네 VM이 모두 같은 방식으로 주소를 받는 것은 아니다. 매체 연결과 그 안에 전달할 네트워크 설정을 나눠 봐야 한다.

DHCP와 고정 주소를 다른 값으로 남겼다

개발용 VM에는 다음 값이 들어 있고 명시적인 게이트웨이 값은 없다.

Text
ipconfig0: ip=dhcp

n8n과 데이터 처리 VM에는 주소와 게이트웨이가 모두 있다. 아래는 실제 값 대신 역할을 표시한 설정 형태다.

Text
ipconfig0: ip=<고정 주소/CIDR>,gw=<게이트웨이>

템플릿에는 ipconfig0 항목이 없다. Proxmox 문서상 Cloud-Init이 활성화돼 있고 IPv4·IPv6 주소를 모두 지정하지 않으면 IPv4 DHCP가 기본값이다. 항목 생략을 곧바로 네트워크 미설정으로 해석하지 않는 이유다. Cloud-Init IP 옵션

여기서 비교한 것은 Proxmox에 저장된 값이다. 게스트 안에서 현재 적용된 주소와 일치하는지, DHCP 임대가 유지되는지는 별도 확인 대상이다. 특히 n8n은 현재 중지 상태라 저장된 설정과 실행 중인 네트워크를 구분해야 한다.

Tailscale 접속은 그 위에 놓인 통로다

개발용 VM에는 DHCP 설정이 있으면서 Tailscale 접속 경로도 있다. 내부 네트워크 인터페이스와 Tailscale 주소가 서로를 대신하는 하나의 설정은 아니다.

현재 직접 SSH 연결을 확인한 경로는 Tailscale·SSH 글에 따로 적었다. 여기서는 VM이 어느 브리지에 붙는지, 초기 주소 설정을 어떻게 전달하는지를 다룬다. VM의 연결 설정과 실제 원격 접속 결과를 이어 보면 어느 단계까지 동작했는지 구분할 수 있다.
